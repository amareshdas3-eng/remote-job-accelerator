# Remote Job Accelerator v4.3 — Deployment-grade hardening

## What changed
- PDF/DOCX/TXT resume ingestion with 5 MB limit and server-side extraction.
- Durable Postgres rate limiting with a security-definer RPC (no process-local limiter).
- Same-origin checks on state-changing browser APIs.
- CSP, HSTS-on-HTTPS, clickjacking, MIME-sniffing and referrer protections.
- SSRF-restricted HTTPS job ingestion with allowlisted hosts, redirect rejection, timeout and response-size limits.
- One-time, hashed extension OAuth codes; the OAuth authorization code is exchanged before storing the 15-minute extension JWT.
- Application PATCH with ownership checks and constrained status values.
- Account export and destructive account deletion endpoints.
- Health endpoint reports dependency configuration without leaking secrets.
- Gumroad webhook remains idempotent and now handles common cancellation/refund flags.

## Supabase
Run `api/schema.sql` in the production project. Never expose `SUPABASE_SERVICE_ROLE_KEY`. Enable email/password authentication and verify redirect URLs. Back up production data and test restore before launch.

## AI provider
Only server routes call the AI provider. Set `AI_API_URL`, `AI_API_KEY`, and `AI_MODEL`. Keep prompts evidence-first. Add provider-side budget/usage alerts.

## Gumroad
Set a high-entropy `GUMROAD_PING_SECRET`. Configure the Ping URL as `/api/webhooks/gumroad/<secret>`. Use the exact product permalink. Test purchase, duplicate webhook, refund/cancel and re-purchase behavior in staging.

## OAuth extension
Create a production OAuth client. Register `${NEXT_PUBLIC_APP_URL}/api/extension/oauth/callback`. Restrict redirect URIs to the production RJA domain and Chrome extension redirect generated by Chrome. Replace `YOUR_RJA_DOMAIN` in `extension/popup.js`, then load the unpacked extension for staging. Do not ship localhost configuration.

## Deployment checklist
1. HTTPS custom domain and production environment variables.
2. Run schema migration and verify RLS policies.
3. Verify `/api/health` is 200 and database is `ok`.
4. Test signup/login/logout and expired sessions.
5. Upload TXT, DOCX and PDF resumes; reject >5 MB and unsupported types.
6. Test job ingestion, redirect rejection and unsupported hosts.
7. Test AI match/tailor/interview and 429 behavior.
8. Test Gumroad active → duplicate → refunded/cancelled → active lifecycle.
9. Test extension OAuth, code replay rejection and expired JWT rejection.
10. Test application create/update ownership boundaries.
11. Test account export and deletion in a disposable account.
12. Configure PostHog/monitoring, error alerts, database backups and restore drill.
13. Run `npm run typecheck`, `npm run build`, and `npm test` in CI before deployment.

## Production security policy
Never log resume contents, OAuth codes, access tokens, AI API keys or payment payloads unnecessarily. Redact PII in error tracking. Apply least privilege to service credentials. Measure outcomes, not AI activity; keep human review for consequential career decisions.


### v4.3 launch checklist
1. Apply `api/schema.sql` (including additive `cover_letter` migration).
2. Configure all `.env.example` secrets in the deployment platform.
3. Set `NEXT_PUBLIC_GUMROAD_URL` to the actual product checkout.

5. Install dependencies and run `npm run typecheck`, `npm test`, `npm run build`.
6. Set the real app URL in the extension before publishing the extension.
7. Run a real browser smoke test: signup → entitlement → evidence import → job → match → tailor → interview → tracker.
8. Confirm export and deletion flows in a staging project before production.
